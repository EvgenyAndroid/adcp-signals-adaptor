## KQ1. What is the current AdCP version line, release cadence, domain coverage, and stated roadmap (3.2 / 3.3 / 4.0)?

### Takeaway
AdCP's current stable line is **3.2** (release artifact `3.2.1`, GA 2026-09-30, wire pin `"3.2"`; `3.2.0` was never published), with `3.2.2` on 2026-10-04 and 3.1.x / 3.0.x still receiving patches. The protocol covers Media Buy, Signals, Creative, Brand (brand.json + rights), Governance, Accounts, and experimental Sponsored Intelligence, over MCP and A2A transports; 3.3 is an additive working-group cycle and **4.0 is a breaking-change window targeted for early 2027** whose floor requirement is mandatory RFC 9421 request signing on spend-committing operations.

### Cited Findings

**Version line and dates**
- AdCP 3.0 was published April 21, 2026, described by AAO as "the most significant expansion of AdCP since the standard launched six months prior" [announced/shipped] — [AgenticAdvertising.org perspectives](https://agenticadvertising.org/perspectives/advertising-finally-has-a-common-language-with-adcp-30-mo93ubxm) (via search summary); repo versioning policy lists "3.0 — April 2026 — GA release" — [adcp repo docs/reference/versioning.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/reference/versioning.mdx).
- "AdCP 3.2 is generally available as release `3.2.1` (published 2026-09-30, wire pin `"3.2"`)… Stable TypeScript and Python SDKs follow the protocol release; Go and Java support for 3.2 is planned as a follow-up." — [adcp repo docs/reference/roadmap.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/reference/roadmap.mdx).
- "The number `3.2.0` was never released… 3.1 stays supported for integrations pinned to `"3.1"`… Send `"3.2"` only after a peer lists it in `get_adcp_capabilities.adcp.supported_versions`." — [adcp repo docs/reference/release-notes.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/reference/release-notes.mdx).
- GitHub Releases (read 2026-10-05): v3.2.2 (Oct 4), v3.2.1 (Oct 1 UTC), v3.1.25 (Oct 1), v3.0.27 (Oct 1, patch to governance storyboards' `governance_agent_url`), v3.2.0-rc.7 (Sep 27), rc.6 (Sep 24), v3.1.24 (Sep 23), rc.4 (Sep 20), rc.3 (Sep 14), v3.1.23 (Sep 14) — [adcp GitHub Releases](https://github.com/adcontextprotocol/adcp/releases). CHANGELOG.md shows the 3.2 line went through beta.0–beta.11 and rc.0–rc.7 before 3.2.1 — [adcp CHANGELOG.md](https://github.com/adcontextprotocol/adcp/blob/main/CHANGELOG.md).
- AdCP 3.1 is "the production-hardening release… additive over 3.0… No breaking changes for 3.0-conformant agents"; it added distributed `brand.json`, dependency-impairment webhooks, wholesale feed mirroring, release-precision version negotiation, signed brand verification, canonical creative formats, vendor-attested measurement goals (naming DV, IAS, Adelaide, TVision, Lumen, Kantar, Upwave, Scope3), and `list_transformers` for creative generation — [adcp repo docs/reference/whats-new-in-3-1.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/reference/whats-new-in-3-1.mdx).
- v2 line: last v2 release was 2.5.3 (January 2026); v2 "no longer supported" at 3.0 GA (April 2026) and "fully deprecated" on August 1, 2026 (UTC); v2-only agents "can be registered but cannot be verified" in the AAO registry — [adcp repo docs/reference/v2-sunset.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/reference/v2-sunset.mdx).

**Release cadence policy**
- "Major releases (breaking): minimum 18 months apart; Next major (4.0): target early 2027; Support for previous major after successor GA: minimum 12 months; Deprecation notice before removal: minimum 6 months… Within a version, releases land every 6–8 weeks early in the cycle and stretch toward quarterly as the version stabilizes." — [adcp repo docs/reference/versioning.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/reference/versioning.mdx).

**Domain coverage**
- v2 scope was "Media Buy, Signals, Creative"; v3 "Adds Brand Protocol, Governance, Sponsored Intelligence (experimental)" plus a named **Accounts Protocol** (`sync_accounts`, `list_accounts`, `report_usage`), first-class `sync_catalogs` (13 catalog types), media planning proposals, brand rights (`get_rights`/`acquire_rights`/`update_rights`, experimental), and a channel model expanded from 9 to "20 planning-oriented channels (including `sponsored_intelligence`) with broadcast TV support (creative identifiers, measurement windows, spot formats)" — [adcp repo docs/reference/whats-new-in-v3.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/reference/whats-new-in-v3.mdx).
- Agents declare `supported_protocols` from six domains: `media_buy`, `creative`, `signals`, `governance`, `brand`, `sponsored_intelligence`, plus narrow `specialisms` (19 in 3.0, e.g. `sales-guaranteed`, `sales-broadcast-tv`, `creative-generative`, `property-lists`, `signal-marketplace`, `brand-rights`) — same source.
- 3.2 "by the numbers" vs 3.1.0: manifested tools 64→78; specialisms 21→31; standard error codes 92→120; JSON Schema files 648→1,017; compliance YAML files 137→237. New 3.2 specialisms include `sales-dooh` (stable) and preview `sales-exchange`, `sales-retail-media`, `sales-streaming-tv`; new compact lifecycle tasks `list_products`, `request_proposals`, `refine_proposals`, `decline_proposals`, `buy_products`, `accept_proposal`, `control_media_buy`; "Reliable Reporting 1.0 (experimental)"; clean-room / data-collaboration `media_buy.audience_activation` (experimental); seller-optimized shared budgets; MediaBuy-level frequency cap; compact MCP schemas "71–94% smaller" than 3.1 facades — [adcp repo docs/reference/release-notes.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/reference/release-notes.mdx) and [whats-new-in-3-2.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/reference/whats-new-in-3-2.mdx).
- Trust surface in 3.0: `idempotency_key` required on every mutating request; RFC 9421 HTTP Message Signatures (Ed25519) "optional in 3.0 and mandatory under AdCP Verified"; `governance_context` is a signed JWS; "AdCP Verified is self-attested in 3.0" (AAO "does not audit the output or gate issuance") — [adcp repo docs/reference/whats-new-in-v3.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/reference/whats-new-in-v3.mdx).

**Transports (MCP / A2A)**
- "AdCP is transport-agnostic: the same task definitions work over both MCP and A2A… MCP… Developed by Anthropic… A2A… Developed by Google" — [adcp repo docs/building/concepts/industry-landscape.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/building/concepts/industry-landscape.mdx). SDKs at L0 must provide "Transport adapters for at least one of {MCP, A2A}; ideally both" — [adcp repo docs/building/by-layer/L0/index.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/building/by-layer/L0/index.mdx). 3.2 added "Compact MCP `2026-07-28` schemas, a 128 KiB MCP interoperability target, the A2A 1.0 profile extension" — [whats-new-in-3-2.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/reference/whats-new-in-3-2.mdx).

**Roadmap: 3.3 and 4.0**
- 3.3 "working-group cycle" workstreams: acts-for authority and multi-agent delegation (#7063); post-acceptance commercial lifecycle — payment terms, FX, fees, settlement, disputes, credits, makegoods (#7064); cross-channel maturity and offline depth — print, broadcast, OOH, audio (#7065); production security profile (#7066); capability/routing ergonomics (#7067); production evidence program (#7068). "incompatible identity, account, or security changes move to the 4.0 accumulation window." — [adcp repo docs/reference/roadmap.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/reference/roadmap.mdx).
- "v4.0 — target early 2027… the next breaking-changes accumulation window… Security (floor): Mandatory request signing for spend-committing operations (RFC 9421)… Canonical formats: Remove every exact `format_ids` field." — same source.
- The roadmap is a public GitHub Project board with Protocol fields "Creative, Media Buy, Signals, Brand Protocol, Governance, SI, TMP, Platform, Website, Addie, Certification" — same source.
- License: "AdCP is open source under the Apache 2.0 license" — [adcp repo docs/faq.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/faq.mdx). (Note: a search-surfaced third-party description called it "MIT-licensed"; the repo FAQ says Apache 2.0, and CHARTER/IPR_POLICY govern contributions — prefer the repo.)

### Inferences
- The 3.x line is in a fast patch cadence (three parallel maintenance branches 3.0.x / 3.1.x / 3.2.x all patched the same week of Oct 1, 2026), consistent with the stated "6–8 weeks early in the cycle" policy and with a spec that is still absorbing production feedback.
- The 3.3 workstreams (settlement, FX, makegoods, offline channels, delegation) are the parts of a HoldCo media-operations stack that AdCP does not yet standardize; a HoldCo evaluating AdCP in Q4 2026 should expect finance/reconciliation gaps until 3.3 ships.

### Gaps
- Exact 3.1.0 GA date was not captured (CHANGELOG contains the entry but I did not extract the date; the 3.0 GA was April 21, 2026 and 3.1 shipped between then and the 3.2 beta cycle).
- The AAO changelog page on docs.adcontextprotocol.org and the GitHub Project board itself were not readable (blocked / GraphQL unavailable), so the live count of Exploring/Accepted RFCs is unknown.

## KQ3. What is IAB Tech Lab's AAMP 2.x (and 3.0), how does it relate to or compete with AdCP, and which buy-side organizations back each?

### Takeaway
IAB Tech Lab's **AAMP (Agentic Advertising Management Protocols)** is a parallel, non-wire-compatible stack: SDKs + roadmap (Jan 6, 2026) → named AAMP (Feb 26, 2026) → **AAMP 2.0** (April 2026: transaction-ready Buyer/Seller Agent SDKs built on OpenDirect/AdCOM/OpenRTB, Agentic Audiences OpenRTB extension, Prebid module, Agent Registry) → **AAMP 3.0 / OpenProposal** draft (Sept 22, 2026; public comment to Oct 22, 2026). AAO itself states AAMP and AdCP "are not wire-compatible merely because both support MCP and A2A." On the buy side, WPP Media's Agentic Standards Initiative names IAB Tech Lab and Prebid.org (not AAO) as partners, while Omnicom, Butler/Till, Horizon-adjacent pilots and Apostra transact on AdCP; no HoldCo has publicly declared exclusive allegiance to AAMP.

### Cited Findings

**AAMP timeline and contents**
- "IAB Tech Lab published buyer and seller agent software development kits (SDKs) alongside an agentic roadmap on January 6, 2026, and on February 26, 2026 named the programme AAMP, the Agentic Advertising Management Protocols. AAMP 2.0 added programmatic guaranteed deals and agentic private marketplaces in April 2026." — [ppc.land: IAB Tech Lab names its agentic ad initiative AAMP](https://ppc.land/iab-tech-lab-names-its-agentic-ad-initiative-aamp-to-end-market-confusion/) (search summary).
- AAMP 2.0 "includes production-ready Buyer Agent and Seller Agent SDKs that allow agents to negotiate, share rate cards and execute programmatic deals within existing standards and defined guardrails, with every action captured and auditable to ensure human oversight for approvals." Buyer Agent SDK "spans media planning, deal creation, discovery, negotiation and campaign automation via a multi-agent framework and a centralised Deals Library, and integrates with the Agent Registry." Seller Agent SDK "adopts standards such as OpenDirect and AdCOM to manage inventory, media kits, pricing and negotiations through a configurable engine and state machine." Also "an Agentic Audiences OpenRTB extension, a Prebid module and an open-source scorer." Supports "Programmatic Guaranteed, Preferred Deals, PMPs, and the open programmatic marketplace, as well as Linear GRPs." — [IAB Tech Lab: AAMP 2.0 Release](https://iabtechlab.com/aamp-2-0-release-brings-transaction-ready-buyer-and-seller-agent-sdks/) and [IAB Canada summary](https://iabcanada.com/transaction-ready-agentic-advertising-enabled-with-iab-tech-lab-aamp-2-0/) (search summaries).
- AAMP 3.0: "IAB Tech Lab announced AAMP 3.0 on September 22, 2026… adds OpenProposal, a specification designed to standardize the part of media buying between an advertiser's brief and a commitment to buy" — [IAB UK](https://www.iabuk.com/news-article/iab-tech-lab-introduces-aamp-30), [PRNewswire via StreetInsider](https://www.streetinsider.com/PRNewswire/IAB+Tech+Lab+Introduces+AAMP+3.0+to+Standardize+the+RFP-to-Buy+Process+for+Agentic+Advertising/27086680.html) (search summaries).
- Primary: "OpenProposal is the core AAMP 3.0 object… **This is a draft.** Nothing here is a ratified IAB Tech Lab standard… Comment period opens 2026-09-22… closes 2026-10-22… You do not need to be an IAB Tech Lab member to comment." Downstream mapping: Direct buy → OpenDirect 2.1; PG → OpenDirect 2.1 + Deals API; PMP → Deals API + OpenRTB 2.6; Open market → OpenRTB 2.6. "Of 71 fields, only 3 require a round trip with the counterparty." Machine-readable schemas "are not published with this first draft." — [IABTechLab/OpenProposal README](https://github.com/IABTechLab/OpenProposal/blob/main/README.md) and [spec/openproposal-3.0.md](https://github.com/IABTechLab/OpenProposal/blob/main/spec/openproposal-3.0.md). Tag `v3.0-draft-1` released Sept 24, 2026 — [GitHub release](https://github.com/IABTechLab/OpenProposal/releases/tag/v3.0-draft-1).
- OpenProposal GOVERNANCE.md as of the draft states working group, chairs, editors and the decision rule are all "`TBD` and will be filled in during the comment period" — [IABTechLab/OpenProposal GOVERNANCE.md](https://github.com/IABTechLab/OpenProposal/blob/main/GOVERNANCE.md).

**Relationship / competition with AdCP**
- AAO's own FAQ: "AdCP is maintained by AgenticAdvertising.org (AAO), an independent specification body — not a subsidiary or working group of IAB Tech Lab… IAB Tech Lab's AAMP initiative… overlaps with AdCP in discovery, planning, negotiation, order and media-buy creation, audiences, governance, reporting, and execution. The frameworks use different primitives and are not wire-compatible merely because both support MCP and A2A… IAB Tech Lab develops AAMP… with input from the Agentic Task Force." AdCP "selectively incorporates or maps IAB Tech Lab standards" (OpenRTB/AdCOM classifications, VAST, DAAST, GPP/TCF, ads.txt/sellers.json) but "defines its own task and transaction model rather than adopting OpenRTB's auction wire protocol or OpenDirect's transaction model." — [adcp repo docs/faq.mdx](https://github.com/adcontextprotocol/adcp/blob/main/docs/faq.mdx).
- "Shailley Singh, chief operating officer of IAB Tech Lab, counted 13 functions on which AAMP and AdCP overlap on August 20, 2026, from buyer and seller agents to human approval before spend. They book through different objects, so an agent built for one does not automatically speak the other." — [ppc.land buyer-agent explainer](https://ppc.land/buyer-agent/) (search summary).
- The Trade Desk-owned publication The Current headlined IAB Tech Lab's agentic roadmap as "don't expect any love for AdCP" — [The Current](https://www.thecurrent.com/data-privacy-iab-tech-lab-ai-agentic-roadmap-adcp) (title only; article blocked).
- Trade-press framing of a standards fight: [Digiday, "Inside the debate over agentic advertising and standards"](https://digiday.com/media-buying/inside-the-debate-over-agentic-advertising-and-standards/); [perform.digital, "AdCP vs AAMP: The Agentic Advertising Standards Fight"](https://perform.digital/blogs/adcp-vs-aamp/); [No Fluff Advisory, "AdCP vs AAMP: The Retrofit and the Greenfield"](https://nofluffadvisory.com/writing/adcp-vs-aamp/); [Agentic Ad Lab comparison](https://agenticadlab.com/protocols/adcp-vs-aamp/) (all blocked; titles only).

### Inferences
- The split is less "HoldCo A backs AAMP, HoldCo B backs AdCP" than a layering: AdCP is where agent-to-agent *transactions* are publicly happening (Omnicom, Butler/Till, MiQ/Magnite, Havas/PubMatic), while IAB Tech Lab/AAMP is where the TV/video establishment (WPP Media + the broadcasters + Prebid) is doing *standards* work, and OpenProposal 3.0 looks designed to retrofit agentic discovery onto OpenDirect/Deals API/OpenRTB rather than replace them.
- OpenProposal's unfilled governance (TBD chairs/decision rule) and absent schemas mean AAMP 3.0 is not implementable as of Oct 2026; AdCP 3.2 is shipping with compliance runners and SDKs. For a white paper, "AAMP 3.0" should be characterized as a draft object model, not a protocol in production.

## KQ6. What pilots, case studies, or reported results exist for agent-to-agent media buys (spend, CPM deltas, time savings)?

### Takeaway
Three quantified public results exist: **Butler/Till + PubMatic + Geloso Beverage Group (Clubtails), Dec 2025** — 82% lower buy-side costs, 30% lower CPMs, 40% more impressions, 5.5x supply-chain cost reduction, 98% VCR, <1% DV failures (AdCP + MCP + Claude on PubMatic AgenticOS); **Magnite + MiQ with Scope3 buyer agent, Dec 2025** — 87% setup-time reduction, 70% faster issue resolution; **Magnite + Amnet (Dentsu) EMEA, 2026** — ~70% CTV setup-time reduction. Omnicom reports live buys for "several clients" with no numbers; Apostra reports "seven-figure campaigns" including a "million-dollar pilot" for an unnamed brand.

### Cited Findings
- Butler/Till + PubMatic (press release Dec 15, 2025): "fully autonomous, end-to-end agentic advertising campaign across CTV for Clubtails, a leading flavored malt beverage brand from Geloso Beverage Group… uses AdCP (Ad Context Protocol), an open protocol from AgenticAdvertising.org… Geloso used Anthropic Claude's large language model (LLM) to interpret media briefs, generate strategy, and execute media buys through PubMatic's AgenticOS, with the companies using Model Context Protocol (MCP) for agent communication" — [PubMatic IR](https://investors.pubmatic.com/news-releases/news-release-details/pubmatic-and-butlertill-launch-adcp-enabled-agentic-ai-campaign), [BusinessWire](https://www.businesswire.com/news/home/20251215976339/en/PubMatic-and-ButlerTill-Launch-AdCP-Enabled-Agentic-AI-Campaign-Across-), [Advanced Television 2025-12-15](https://www.advanced-television.com/2025/12/15/pubmatic-butler-till-launch-adcp-enabled-agentic-ai-campaign-across-ctv/) (search summaries) [shipped].

### Inferences
- All quantified results come from single-campaign SSP-sponsored pilots with vendor-published numbers (PubMatic, Magnite); none is independently audited, and the headline cost savings are mostly removed DSP/intermediary fees rather than negotiated media-price improvements.

### Gaps
- No HoldCo has published spend volumes, CPM deltas, or time savings for AdCP/MCP buys.
- The WPP Media Buyer Agent for Video and Stagwell/TTD Koa pilots have no published results as of Oct 5, 2026.
- Full text of the Butler/Till, Magnite and Omnicom case material could not be read, so secondary details (flight dates, budgets, publisher lists) are missing.
